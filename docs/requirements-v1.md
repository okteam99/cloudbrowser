# cloudbrowser V1 需求与设计方案

日期：2026-10-20

状态：需求草案；已确认目标与候选实现分开记录。

## 1. 产品目标

提供一个部署在服务器上的浏览器执行环境。用户描述目标，Agent 根据 Skill 创建指定环境的浏览器实例，模拟正常用户完成浏览器流程，验证每一步和最终结果，返回有证据的结论。

通过列表与详情页、表单和文件下载等通用场景验收浏览器能力。新增场景通过 Skill 和测试数据配置。

## 2. 已确认需求

1. 使用 Docker 部署到服务器。
2. 无需 Web 管理页面。
3. 创建浏览器实例时可指定 UA、尺寸和代理 IP。
4. 代理支持协议、地址、端口、用户名和密码。
5. 由 Agent / Skill 灵活选择 URL、可用代理、配置和操作流程。
6. 支持浏览器内操作，包括下载及其结果验证。
7. 不包含原生手机 App、操作系统界面自动化或安装、执行下载文件。
8. 支持多种场景，由 Skill 配置网址、操作步骤和成功标准。

## 3. 总体结构

```text
用户指令 / 外部定时调度
          ↓
Agent + 场景 Skill
          ↓ MCP
远程 Docker 浏览器服务
  ├─ 实例与页面管理
  ├─ 设备环境与代理
  ├─ 浏览器交互
  ├─ 诊断和证据采集
  └─ 下载与产物管理
```

服务负责可靠执行及返回事实，Skill 负责规划和业务判断。Skill 不负责代理密码存储。浏览器服务不内置模型调用、业务流程或定时 Agent。

## 4. 浏览器实例

### 4.1 创建参数

| 参数 | 含义 |
| --- | --- |
| `user_agent` | 自定义 UA；未指定时使用浏览器默认值 |
| `viewport.width/height` | 页面内容区域宽高，单位为 CSS 像素 |
| `proxy.server` | 代理协议、地址和端口 |
| `proxy.username/password` | 可选鉴权，输入与日志分离 |
| `proxy_id` / `proxy_ref` | 控制台保存代理的 ID / 兼容旧预配置引用 |
| `mobile.enabled/touch/device_scale_factor` | 可选移动环境配置 |
| `locale/timezone` | 可选语言和时区 |
| `idle_timeout/max_lifetime` | 在服务上限内设置生命周期 |

`proxy`、`proxy_id` 与 `proxy_ref` 三选一。可以不指定代理用于明确请求的直连任务；指定代理后不得失败回退直连。

尺寸以页面视口为 V1 标准，不以浏览器外框为标准。手机 UA、移动设备属性和手机视口是不同设置，服务需返回实际生效值及不一致提示。

### 4.2 生命周期与隔离

- 创建成功返回唯一 `instance_id`。
- 状态：创建中、可用、异常、关闭中、已关闭。
- 不同实例隔离代理、Cookie、缓存、存储与登录状态。
- 同一实例中新标签页、弹窗继承该实例环境。
- 环境在实例存活期间固定；切换 UA 或代理时新建实例。
- 临时配置随实例关闭清理，证据与下载按保留策略保存。
- 断连后允许限定时间内重连，超时自动回收；不承诺服务重启后保留浏览器进程。
- V1 默认不跨任务持久化登录状态；导入导出登录态属于后续独立需求。

### 4.3 环境验证

区分“实例创建成功”和“测试环境验证成功”。返回配置值与实际值：页面读取到的 UA、视口、触控属性、实际出口 IP，以及可选的地理识别来源和时间。

国家由代理出口实现，不是独立浏览器属性。配置标签与实际 IP 识别冲突时单独报告。

请求头 UA、网页可见 UA 与 Client Hints 的一致性需要验证；未通过验证不得声称完整手机模拟。浏览器模拟不等于真机或当地运营商网络。

## 5. 代理

- V1 支持 HTTP 代理、HTTPS 目标 CONNECT 和 SOCKS5，含用户名密码鉴权。
- 服务器配置可按名称、国家和标签管理代理；Agent 可自主选用已授权代理。
- 带鉴权 SOCKS5 的浏览器兼容性需先做技术验证，必要时加入实例级内部代理适配层。
- 测试实际出口、域名解析路径与连接失败行为，不能只验证参数保存成功。
- 代理错误返回明确分类：鉴权失败、不可达、超时、环境不匹配。
- 出口校验默认在测试前执行；连接故障或敏感场景可再次校验。
- 网页请求、浏览器后台流量和可能的旁路路径需要明确控制与测试，不能只靠 IP 查询证明不存在旁路。

代理凭据不写入 Skill、截图说明、普通日志或 MCP 代理列表；管理页在登录后明文展示，优先使用 `proxy_id`。直接传入凭据时同样需脱敏。

## 6. MCP 工具设计（候选接口）

| 工具 | 功能 |
| --- | --- |
| `list_proxies` / `check_proxy` | 列举已授权代理、检查连接和出口 |
| `create_instance` / `get_instance` / `list_instances` / `close_instance` | 管理实例 |
| `create_page` / `list_pages` / `close_page` | 管理标签页和弹窗 |
| `navigate` | 打开、刷新、前进和后退 |
| `snapshot` | 获取可见内容、结构和元素引用 |
| `interact` | 点击、输入、滚动、选择、按键等 |
| `wait_for` | 等待元素、URL、状态或事件 |
| `handle_dialog` | 处理网页提示、确认框、输入框 |
| `screenshot` | 保存页面截图 |
| `upload_file` | 上传已授权的产物或文件 |
| `list_downloads` | 查询下载状态与文件元信息 |
| `get_diagnostics` | 查询跳转、响应、请求失败、控制台错误 |
| `get_artifact` | 获取截图、诊断和下载产物 |

工具名称可在实现阶段调整。输入以 `instance_id`、`page_id` 定位，不依赖当前激活窗口。元素引用需有过期语义，页面变化后重新获取快照。

统一返回操作 ID、状态、数据、产物引用及结构化错误。单步耗时超过交互预算时返回可查询的操作 ID，支持取消；客户端重连后可查询执行状态。

读取可有限重试。点击、提交、上传等操作结果未知时，先查询执行状态，不盲目重复。业务通过与工具执行成功分别表达。

V1 不提供通用 Shell 或无限制网页脚本工具。页面读取、iframe、弹窗和下载的覆盖能力通过专门工具验证。

## 7. 浏览器操作与下载

覆盖访问页面、点击、输入、滚动、选择、按键、iframe、多标签页、网页弹窗、上传与下载。

下载记录：状态、原始文件名、产物 ID、大小、内容类型、校验值、来源页面及失败原因。可按场景增加空文件、格式和内容验证；文件扩展名或 Content-Type 不能单独证明内容有效。

上传仅使用明确授权的文件。文件通过产物引用传递，禁止任意宿主路径读取。文件名和路径需规范化，防止覆盖或路径穿越。

## 8. Skill 与场景

每个场景描述目标、参数、环境选择、正常路径、通过标准、异常策略、允许的副作用及报告格式。

支持临时探索式任务和固化回归任务。固定流程可使用受约束的辅助脚本优化，但必须经过相同的实例隔离、权限与记录机制，不形成另一套绕过 MCP 的执行路径。

平台统一结果状态：通过、失败、阻挡、跳过、未完成。场景决定业务含义，例如“空列表”是否为失败。

列表与详情页场景：

- 访问调用者指定的列表页面。
- 使用授权国家代理和 Android 手机环境。
- 校验出口与设备配置，再检查列表。
- 随机选择 5 个不同条目；不足 5 个测试全部并记录不足。
- 记录抽样清单、条目去重依据，跟踪新页面及最终跳转。
- 最终有效内容才算通过；空白、错误 JSON、循环跳转不能算通过。
- 不安装、注册、领取奖励或购买。
- 使用测试环境或测试标记，便于识别自动化访问。

另一个验收场景：受控测试页面的搜索、表单或文件下载流程，验证完整操作路径与预期结果。

## 9. 诊断与证据

记录任务与操作 ID、起止时间、实例配置（脱敏）、出口、页面地址、步骤结果、重试过程及必要截图。

按需保存响应状态、跳转链、失败请求、控制台错误。首次失败和重试结果都保留，区分首次通过与重试通过。

文件与诊断通过 MCP 返回受控产物引用，避免将仅服务器可访问的本地路径当作用户可下载地址。定义文本读取、分块传输或导出方式及大小上限。

结构化 JSON 是通用事实记录，Agent 生成可读总结。不默认保存全部响应正文、Cookie、鉴权头或包含密码的输入内容。

## 10. 部署方案（候选实现）

采用 Playwright + 配套浏览器的版本固定镜像。V1 先支持 Chromium；浏览器引擎扩展独立规划，不将 iPhone UA 声称为真实 Safari。

对每个实例使用独立进程及临时用户目录，优先隔离可靠性，再按实际资源测试优化。

目标启动形式：

```sh
docker run -d \
  --name browser-mcp \
  --restart unless-stopped \
  --shm-size=1g \
  -v browser-mcp-data:/data \
  -v /srv/browser-mcp/config:/config:ro \
  browser-mcp:<version>
```

以上镜像名是目标接口示意，不代表镜像已发布。

无需映射公网端口。Agent 通过 SSH 执行容器内 stdio 接入命令；容器内常驻实例管理器持有浏览器，接入进程通过本地 IPC 通信。协议输出走 stdout，诊断走 stderr 或日志文件。

不挂载 Docker socket，不暴露浏览器调试端口。SSH 接入账号的权限与容器接入命令应受限制；使用 Docker 权限的宿主接入需明确其权限边界。

配置控制并发、页面数、空闲超时、最大存活时间、下载大小、磁盘配额、保留期限及目标网络访问范围。

## 11. 安全与副作用

- 默认阻止未授权内网、云元数据地址、本地文件和浏览器特权页面；内部站点测试显式授权。
- URL 及每次重定向、解析后的地址均纳入网络策略，考虑 DNS 重绑定和代理端解析。
- 页面内容是数据，不能改变 Agent 指令或授权。
- 登录、提交、注册、发送消息、下单等由具体场景约定授权范围；浏览器内操作也可能改变生产数据。
- 下载文件不安装、不执行；验证码或权限阻挡明确报告。
- 每个连接仅访问其授权实例与产物；即使 V1 单用户，也保留实例所有权校验。

## 12. 定时执行

此前提出的每小时测试保留为后续场景运行要求，不内置在通用浏览器服务中。

服务器上的调度器启动 Agent，加载场景 Skill 并连接 MCP；需明确模型凭据、运行预算、任务锁、整轮超时和通知渠道。聊天关闭后仍能执行的前提是服务器具备完整 Agent 执行环境。

不重叠运行；失败有限重试。每轮保存结果，通知策略由用户决定。当前尚未部署或启用定时任务。

## 13. 验收标准

1. 按部署文档启动容器并完成 MCP 连接，不需要 Web 页面或 Chrome 插件。
2. 指定 UA、视口、代理后，查询可验证实际生效值。
3. HTTP 与带鉴权 SOCKS5 通过真实网络验证；代理失效不能直连。
4. 至少两个实例隔离出口和会话；新页面继承所属实例环境。
5. 完成点击、输入、滚动、选择、iframe、弹窗和多标签页流程。
6. 下载完成后可查询、校验并通过 MCP 获取产物；上传限定在授权文件范围。
7. 超时、断连、浏览器崩溃可区分报告，过期资源可回收。
8. 操作结果未知时不重复提交，首次失败不被重试覆盖。
9. 至少两个不同场景使用同一镜像完成测试，复用相同浏览器工具。
10. 报告有证据且不泄漏凭据，产物访问和网络边界可验证。

## 14. 分阶段交付

1. 最小闭环：实例创建、UA/视口/代理校验、导航、截图、关闭。
2. 交互能力：元素、iframe、标签页、弹窗、上传下载和诊断。
3. 场景验收：列表与详情页及受控下载/表单场景、报告及故障注入验证。
4. 无人值守：外部 Agent 调度、防重叠、预算、数据清理和通知。

每阶段以实际验收结果推进，不因配置接受成功就声称功能已生效。

## 15. 实现前待定项

- 第一版部署机器架构、资源和预期并发。
- 默认与最大超时、下载限额、文件保留期限。
- 服务器是否具备 Agent 执行器及模型访问方式。
- 敏感写入场景的授权规则、登录态持久化需求。
- 通知目的地和是否需要每轮完整摘要。

这些不阻止核心浏览器能力的技术验证，但不得用未确认的默认值冒充用户决定。
